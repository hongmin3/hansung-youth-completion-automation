1. 목적

청년부 교육 담당자는 양육 수료자 명단을 Google Sheet에 모아 둔다. 지금까지는 사람이 디모데 웹 화면에서 한 명씩 검색해 입력했다. 이 자동화는 그 일을 대신해 수료내역을 자동으로 등록한다.

명단은 수백 행에 이른다. 같은 입력을 이만큼 되풀이하면 사람은 동명이인에게 잘못 입력하거나 같은 내용을 두 번 입력하기 쉽다. 이런 실수를 없애는 것이 목적이다.

성공 조건은 다음과 같다.

  • 명단의 각 행은 확정된 동일인에게만 수료내역으로 등록된다.
  • 시트의 입력여부는 등록에 성공한 행, 또는 같은 과정이 이미 등록되어 있던 행만 체크된다.
  • 누구인지 확정하지 못한 행은 입력하지도 체크하지도 않고, 그 사유를 남긴다.

이 문서에서 쓰는 말

아래 말에는 docs/SPEC.html에서 마우스를 올리면 뜻이 보인다.

용어뜻
디모데교인 정보를 다루는 웹 화면이다. 이 자동화가 수료내역을 입력하는 곳이다.
수료자 명단교육을 마친 사람을 모아 둔 Google Sheet 표다. 열은 구분 / 군 / 팀 / 이름 / 핸드폰 / 담당자 / 입력여부 순서다.
수료내역디모데에 교인마다 남기는 교육과정 수료 기록이다.
드라이런디모데와 시트를 바꾸지 않고, 누구를 찾았고 어떻게 판정했는지만 확인하는 실행이다. 옵션 없이 실행하면 드라이런이다.
실제 입력(--execute)디모데에 저장하고 시트에 체크까지 하는 실행이다.
동일인 확정명단의 한 행이 디모데의 어느 교인인지 한 사람으로 정하는 일이다.
교육과정 구분(구분)시트에서 과정 이름이 적힌 열이다. 예: LTC, 확신반.
소속 군(군)시트의 소속 열이다. 비교할 때는 괄호 부분을 뗀다(신군(아하) → 신군).
입력여부시트 G열의 체크박스다. 체크되어 있으면 디모데에 등록되어 있다는 뜻이다.
핸드폰시트 E열의 전화번호 칸이다. 비어 있으면 디모데에서 찾아 채울 수 있다.
담당자시트의 담당자 열이다. 디모데의 강사명으로 들어간다.
청년 A/B디모데의 교인 구분이 교인 > 청년 (A) 또는 (B)인 사람이다.
교육과정 매핑시트 구분 값을 청년-으로 시작하는 디모데 과정명으로 바꾸는 표다.
제외 과정기초반, 예배학교, 결혼예비학교다. 지금은 입력하지 않는다.
교인 상세 창디모데에서 교인 한 명의 정보를 여는 창이다. 여기서 같은 과정이 있는지 보고 저장한다.
시트행결과 CSV에 적는 원본 시트의 행 번호다. 데이터 행은 2부터 센다.
처리 상태행마다 남는 처리 결과다. 입력완료, 이미입력됨 같은 여섯 가지가 있다(REQ-REPORT-001).
선택자프로그램이 디모데 화면에서 버튼이나 입력 칸을 찾을 때 쓰는 표시다.
OAuthGoogle 계정으로 시트 접근을 허락받는 방식이다. 승인하면 토큰 JSON 파일이 생긴다.
쿠키 방식OAuth 없이 GOOGLE_COOKIES로 시트를 CSV로 내려받는 방식이다. 드라이런의 임시 수단으로만 쓴다.
Playwright브라우저(Chromium)를 프로그램으로 조작하는 도구다.
실행 옵션실행 명령 뒤에 붙이는 설정이다. 예: --limit N.
config.py이 컴퓨터에만 두는 비밀 설정 파일이다. 저장소에 넣지 않는다.
output/결과 CSV를 저장하는 폴더다.
result_log.txt행을 처리할 때마다 한 줄씩 쌓이는 실행 로그다.

2. 프로젝트 범위

포함

  • Google Sheet(또는 같은 열 구조의 CSV)에서 수료자 명단을 읽는다.
  • 디모데 청년관리 > 교인검색(청년) 화면에서 명단의 사람을 찾아 동일인으로 확정한다.
  • 허용된 청년- 교육과정만 수료내역으로 등록한다.
  • 같은 과정이 이미 등록되어 있는지 확인해 두 번 등록되지 않게 한다.
  • 성공한 행에만 시트의 입력여부 체크박스와 새로 찾은 전화번호를 적는다.
  • 행마다 처리 결과를 CSV와 로그로 남긴다.
  • 실제로 입력하지 않고 대상과 판정 결과만 확인하는 드라이런을 제공한다.

제외

  • 명단 자체를 모으고 다듬는 일. 시트 내용의 오탈자는 사람이 고친다.
  • 디모데에 없는 교인을 새로 등록하는 일. 교인은 만들지 않는다.
  • 기초반, 예배학교, 결혼예비학교 입력. 지금은 입력하지 않기로 정해 둔 과정이다.
  • 수료가 아닌 다른 상태(미수료, 수강중 등)의 등록.
  • 교육과정 삭제·수정. 이 자동화는 새로 등록만 한다.
  • 예약 실행, 사람 없이 돌리는 실행. 사람이 지켜보면서 직접 실행한다.
  • Apps Script 쪽 일. 그 기준은 ../newacts-newcomer-automation/에 있다.

3. 시스템 구성

구성 요소책임

completion_automation.py나머지 일을 모두 맡는다. 옵션 읽기, 시트 읽기, 디모데 로그인·검색·동일인 판정·중복 확인·저장, 시트 갱신, 결과 기록이다.
config.example.py공개해도 되는 설정 항목의 예시다. 복사해서 config.py로 쓴다.
config.py이 컴퓨터에만 두는 비밀 설정이다. 저장소에 넣지 않는다.
requirements.txt설치해야 하는 Python 패키지 목록이다.
knowledge/AI 에이전트가 작업할 때 쓰는 판단 규칙이다. 사양을 베껴 두지 않고 참조만 한다.
output/실행 결과 파일(드라이런 계획 CSV, 실제 실행 결과 CSV)을 저장하는 곳이다.

이 자동화가 바깥 시스템과 만나는 곳은 세 군데다.

  1. Google Sheets: 명단의 원본이고, 입력여부를 적는 곳이다. 읽을 때는 Sheets API(OAuth)나 CSV 내려받기(export)를 쓴다. 쓸 때는 Sheets API만 쓴다.
  2. 디모데 웹(청년 관리): Playwright Chromium으로 조작하는 화면이다. ASP.NET 프레임으로 되어 있다. 공개 API가 없어서 화면 요소를 찾는 선택자(DOM selector)에 기댄다.
  3. 로컬 파일 시스템: 설정, OAuth 자격 증명, 결과 CSV, 실행 로그를 둔다.

4. 전체 동작 흐름

  1. 실행 옵션을 읽어 실행 방식(드라이런 또는 실제 입력)과 처리할 범위를 정한다.
  2. Google Sheets 자격 증명을 준비한다. 실제 입력에서는 반드시 있어야 한다. 단, 체크를 미루는 옵션을 쓰면 없어도 된다.
  3. 명단을 읽는다. 각 행에 원본 시트의 행 번호를 붙인다.
  4. Playwright로 Chromium을 띄우고 디모데에 로그인한 뒤 교인검색(청년) 목록으로 간다.
  5. 행마다 아래 "행 하나 처리하기" 차례를 따른다.
  6. 브라우저를 닫고 행마다의 결과를 output/ 아래 CSV로 저장한다.

행 하나 처리하기:

  1. 입력여부가 이미 체크되어 있으면 건너뛴다.
  2. 구분을 허용된 교육과정으로 바꾼다. 바꿀 과정이 없거나 제외 과정이면 교육과정매핑없음으로 남긴다.
  3. 전화번호가 비어 있고 보완 조회가 켜져 있으면 이름·군·A/B로 전화번호를 찾아 채운다.
  4. 전화번호가 있으면 전화번호로 검색한다. 이름+전화번호가 딱 한 사람과 맞으면 그 사람으로 정한다.
  5. 찾지 못했으면 이름으로 검색한다. 이름+군이 같고 교인 구분이 청년 A/B인 사람이 정확히 한 명일 때만 확정한다.
  6. 확정하지 못했거나 여러 명이 맞으면 입력하지 않고 사유 상태를 남긴다.
  7. 드라이런이면 드라이런확인으로 끝낸다.
  8. 실제 입력이면 교인 상세 창을 열어 같은 과정이 있는지 본다. 없을 때만 저장한다.
  9. 저장에 성공했거나 이미 등록된 것을 확인한 뒤에만 시트의 입력여부를 체크한다.

REQ-SHEET-001 수료자 명단 읽기

verified구현 completion_automation.py (load_sheet_rows)테스트 TEST-DRYRUN-001 (수동)참조됨 REQ-SHEET-002, TEST-DRYRUN-001변경 이력 CHANGELOG에 이 ID로 기록된 변경 없음

목적

수료자 명단을 정해진 열 순서로 읽는다. 각 행에는 원본 시트의 행 번호를 함께 붙여 둔다.

동작

명단은 다음 세 곳 가운데 하나에서 읽는다.

  • (a) Sheets API로 읽은 대상 탭의 A:G 범위
  • (b) --sheet-csv로 지정한 CSV 파일
  • (c) OAuth 자격 증명이 없을 때 쿠키로 내려받은 CSV(export)

읽은 명단은 이렇게 다룬다.

  • 열 순서는 구분 / 군 / 팀 / 이름 / 핸드폰 / 담당자 / 입력여부여야 한다.
  • 첫 행은 머리글로 본다. 데이터 행에는 시트 기준 행 번호를 2부터 붙인다.
  • 이 번호는 뒤에서 시트를 고칠 때와 결과 CSV의 시트행 값을 적을 때 기준이 된다.
  • API 응답은 행 끝쪽의 빈칸을 빼고 올 수 있다. 그래서 열 수가 모자란 행은 빈 문자열로 채워 머리글과 길이를 맞춘다.

기대 결과

  • 쿠키 방식에서 401이 오면 쿠키가 만료됐다고 알리고, OAuth 설정 방법을 안내한 뒤 멈춘다.

9. 오류 처리 정책

다시 시도하지 않는다

검색이나 저장이 실패해도 저절로 다시 해 보지 않는다. 다시 할 때는 사람이 원인을 확인한 뒤 프로그램을 다시 실행한다.

이유 중복 방지(REQ-INPUT-001)가 있어서 다시 실행해도 안전하다.

일부만 성공해도 계속한다

확정 실패, 여러 명 일치, 과정 매핑 없음은 그 행의 상태로 기록하고 다음 행으로 넘어간다. 한 사람 때문에 전체 실행을 멈추지 않는다.

실행을 멈추는 경우

다음은 행의 상태로 남기지 않고 실행 전체를 멈추는 사유다.

  • SHEET_URL에서 스프레드시트 ID를 얻지 못했다.
  • 쿠키 만료(401)로 명단을 읽지 못했다.
  • --execute인데 필요한 OAuth 클라이언트 파일이 없다.
  • Playwright가 설치되어 있지 않다.
  • 로그인에 실패했거나 화면 구조가 바뀌어 검색 화면까지 가지 못했다.

기록 위치

  • 행마다의 결과는 output/의 CSV와 result_log.txt에 남는다.
  • 로그는 행을 처리할 때마다 바로 덧붙인다. 그래서 중간에 멈춰도 어디까지 했는지 알 수 있다.
주의

결과 CSV는 실행이 끝까지 가야 저장된다.

선택자가 맞지 않을 때

디모데 화면 구조가 바뀐 것 같으면 실제 입력을 멈추고 드라이런부터 다시 확인한다. 근거 없이 선택자를 바꾸지 않는다.

10. 보안 요구사항

  • 로그인 수단은 두 가지다.
    • 디모데 ID와 비밀번호(설정 파일)
    • Google Sheets OAuth 토큰(로컬 JSON)
  • 쿠키 방식은 드라이런에서 임시로만 쓸 수 있다. 운영에는 쓰지 않는다.
  • 저장소에 들어가면 안 되는 것: config.py, OAuth 클라이언트·토큰 JSON, 쿠키 값, output/, user_data/, result_log.txt, 디버그 HTML·이미지.
  • 접근 범위: Google 쪽은 Sheets 접근 권한(scope) 하나만 쓴다. 디모데 쪽은 그 계정이 원래 가진 청년관리 권한을 넘지 않는다. 이 자동화는 권한을 넓히지 않는다.
  • 토큰이 만료되면 갱신용 토큰(refresh token)으로 새로 받는다. 받은 결과는 같은 로컬 파일에 다시 적는다.
  • 에이전트는 설정 파일과 자격 증명 파일의 내용을 열어 응답에 싣지 않는다.

13. 미확정 사항

  • 수료일·수료연도가 코드에 고정되어 있다. 20260621 / 2026이 고정값이라 다음 기수에는 반드시 코드를 고쳐야 한다. 이 값을 설정 항목이나 실행 옵션으로 뺄지, 뺀다면 시트의 열로 받을지 정하지 않았다.
  • 제외 교육과정을 결국 어떻게 할지. 기초반, 예배학교, 결혼예비학교는 "추후 확정 후 사용자 요청 시"라고만 적혀 있다. 디모데의 정확한 과정 이름도, 입력할지도 정하지 않았다.
  • 불리지 않는 팀 비교 함수. 확정하는 길은 이름 + 군 + 청년 A/B이고, 팀은 판정에 쓰지 않는다(2026-09-19 확정, 문서를 코드에 맞춤).
    • identity_matches, normalize_team은 만들어만 두었고 어디서도 부르지 않는다.
    • 이 둘을 지울지, 시트 소속 확인에 쓸지는 정하지 않았다.
  • --defer-sheet-checks를 쓴 뒤 할 일. 미룬 체크를 누가 어떻게 맞출지 정한 절차가 없다.
    • 이 옵션을 켜도 OAuth 파일이 있으면 체크가 그대로 된다.
    • 이것이 의도인지(자격 증명이 있으면 체크한다), 아니면 늘 미뤄야 하는지 정하지 않았다.
  • 자동 테스트를 어디까지 더할지. 지금은 저장소 위생 검사(TEST-HYGIENE-001)만 있다. 입력만으로 결과가 정해지는 함수(format_phone, normalize_group, is_checked, course_map)를 단위 테스트로 확인할지, Playwright 경로도 대상으로 할지 정하지 않았다.
  • 결과 CSV와 실행 로그를 얼마나 둘지. 개인정보가 들어 있는데 정리 주기나 지울 기준이 없다.
  • Owner. 저장소에 운영 책임자가 적혀 있지 않다.

14. 향후 개선 후보

  • 수료일·수료연도·상태를 시트 열이나 실행 옵션으로 받는다. 그러면 기수마다 코드를 고치지 않아도 된다.
  • 결과 CSV 파일 이름에 실행 시각을 넣는다. 그러면 이전 실행 결과를 덮어쓰지 않는다.
  • 입력만으로 결과가 정해지는 함수에 단위 테스트를 더한다. 저장해 둔 HTML 화면 파일(fixture)로 parse_person_card를 확인하는 테스트도 더한다.
  • 디모데 화면 선택자를 한곳에 모은다. 그러면 화면이 바뀔 때 고칠 곳이 줄어든다.
  • 정확한교인없음 행만 모아 후보 목록과 함께 출력한다. 그러면 사람이 판단하기 쉬워진다.
